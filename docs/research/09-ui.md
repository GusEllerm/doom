### 1.3 Skill menu (wimp message, gameskill enum)

`newgame_e { killthings, toorough, hurtme, violence, nightmare }` → maps 1:1 to
`gameskill_t sk_easy..sk_nightmare` passed as `choice` to `G_DeferedInitNew`.
There is **no "too wimpy" message in the Doom 1.10 source** — grep for `wimp` only hits
`dstrings.c` `endmsg[]` entries `"suck it down, asshole!\nyou're a fucking wimp!"`, which is
a **FinalDOOM (DOOM2) quit taunt**, indexed past `NUM_QUITMESSAGES` (22) and never used by
Doom 1 (Doom1 uses endmsg[0..7] only; `M_QuitDOOM`: `endmsg[(gametic%(NUM_QUITMESSAGES-2))+1]`
in the original arrays — with only 8 compiled in for doom1 the usable set is the 8 DOOM1
strings). Our Doom1 target: 8 taunts, or original text (see §4 IP note).
The only skill-related confirm is Nightmare: `M_ChooseSkill(nightmare)` →
`M_StartMessage(NIGHTMARE, M_VerifyNightmare, true)` with
`NIGHTMARE = "are you sure? this skill level\nisn't even remotely fair.\n\n" PRESSYN`
(d_englsh.h:53).

Episode *names* are **not strings in the executable** — they are baked into the `M_EPI1..4`

intermission art for a 4th episode → treat as 4 episodes (final count to cross-check with

### 1.5 M_Responder: keyboard + mouse hit-test (quoted)

There is **no pixel hit-test**; the mouse is a virtual d-pad (m_menu.c, M_Responder):

```c
if (ev->type == ev_mouse && mousewait < I_GetTime()) {
    mousey += ev->data3;
    if (mousey < lasty-30) { ch = KEY_DOWNARROW; mousewait = I_GetTime() + 5; mousey = lasty -= 30; }
    else if (mousey > lasty+30) { ch = KEY_UPARROW; ... }
    mousex += ev->data2;   // ±30 → LEFT/RIGHTARROW, same 5-tic repeat
    if (ev->data1&1) { ch = KEY_ENTER;   mousewait = I_GetTime() + 15; }
    if (ev->data1&2) { ch = KEY_BACKSPACE; mousewait = I_GetTime() + 15; }
}
```

Keys: arrows move `itemOn` (wrap, skipping `status==-1` spacers); left/right call the
status-2 item's routine with 0/1; Enter calls `routine(itemOn)` + `sfx_pistol`; Esc closes
menus (`M_ClearMenus`), Backspace = prevMenu; any letter selects the item whose `alphaKey`
matches (search forward then wrap). While `messageToPrint`, only `' '`, `'y'`, `'n'`, `'N'`,
Esc pass (case-insensitive 'y' check is in the routine: `if (ch != 'y') return;` — responder
upper-cases? No: it forwards raw ch; routines compare lowercase 'y' — keyboard yields
lowercase). Save-string edit mode captures all chars 32–127 up to
`SAVESTRINGSIZE-1=23` chars / `(24-2)*8` px width. Skull cursor drawn at `x-32,
menu->y-5+itemOn*16`; messages are centered: `y = 100 - StringHeight/2`, each line
`x = 160 - StringWidth/2`, line advance `hu_font[0]->height`, `\n` = +12 in M_WriteText.

Confidence §1: HIGH (read m_menu.c fully; quotes verbatim).

## 3. Font mechanism (hu_stuff.c HU_init/HU_LoadGraphics)

**Per-character patch lumps**, ASCII range `'!'` (33) to `'_'` (95) → 63 glyphs
(`HU_FONTSTART '!'`, `HU_FONTEND '_'`, hu_stuff.h:30–34). Loader (hu_stuff.c:405–410):

```c
j = HU_FONTSTART;
for (i=0;i<HU_FONTSIZE;i++) {
    sprintf(buffer, "STCFN%.3d", j++);
    hu_font[i] = (patch_t *) W_CacheLumpName(buffer, PU_STATIC);
}
```

So lumps `STCFN033`…`STCFN095` (STCFN046='.', STCFN058=':' are referenced separately in
HU_ level-ticker code via `HU_FONTSTART` indexing). Space is lump `STCFN032`? No — space is
implicit: `HU_` advance uses width of STCFN for char but range starts at '!'; lowercase
mapped via `toupper` in hu_lib draw. Drawing uses `V_DrawPatch` per char, advance =
`patch->width` (variable width); `hu_font[0]->height` used for line height. Text width
helper: `SHORT(hu_font[ch - HU_FONTSTART]->width)` loops in hu_lib.c.

Confidence §3: HIGH (quote verbatim).

## 4. HUD messages (hu_stuff.c + d_englsh.h)

Mechanism (this 1.10 tree; note: Doom 1.9 used `player->messageTics` — here it is the HU
widget timer, same visible behavior):

- Gameplay sets `plr->message = GOTXXX` (p_inter.c). `HU_Ticker` (hu_stuff.c:511–533):
  ```c
  if (message_counter && !--message_counter) { message_on = false; ... }
  if ((plr->message && !message_nottobefuckedwith) || (plr->message && message_dontfuckwithme)) {
      HUlib_addMessageToSText(&w_message, 0, plr->message);
      plr->message = 0;  message_on = true;  message_counter = HU_MSGTIMEOUT; ...

  ```
  `HU_MSGTIMEOUT = 4*TICRATE` = 4 s (hu_stuff.h:44); `message_dontfuckwithme` set for

  (hu_stuff.h:39–42) — top-left of screen; erased/redrawn in `HU_drawEverything` via
  `HUlib_drawSText` (hu_lib.c:231+, color `CR_GOLD` in HUlib_drawLine).

## 5. Automap (am_map.c — located, single file)

Modes/state: single overlay-or-fullscreen map. `'0'` (AM_GOBIGKEY) toggles fullscreen
(`am_whichelems`… actually `togglemap`/`AM_goBigKey`: sets `f_e` flags to full screen);
`'f'` follow mode (default on when moving), `'g'` grid, `'m'` mark spot, `'c'` clear marks
(10 mark points max), TAB toggles map (AM_STARTKEY/AM_ENDKEY), arrows pan
(AM_PAN*KEY, speed `FINE-ANGLES`… `SPD` constant), `'='`/`'-'` zoom (AM_ZOOMIN/OUTKEY:
`M_ZOOMIN = 1.02*FRACUNIT` per tic, i.e. 2%/tic continuous while held; stops at
min/max_scale_mtof; entry `INITSCALEMTOF = .2*FRACUNIT`). So Doom1 HAS zoom+pan
(both), contrary to some folklore. `idspispopd`-style AMAP cheat
(`cheat_amap_seq {0xb2,0x26,0x26,0x2e}` = typed sequence) cycles `cheating` 0→1→2
(show all lines / thin-two-sided colors / nothing). There is NO red mode in Doom 1.10 —
the “red automap” memory comes from the wall palette itself (below); sourceport red-mode
(Boom colormaps) is not here.

Line colors (AM_drawWalls, am_map.c:1117–1162, quoted): one-sided
`AM_drawMline(&l, WALLCOLORS+lightlev)`; teleporter special 39
`WALLCOLORS+WALLRANGE/2`; secret lines (ML_SECRET) `SECRETWALLCOLORS` only when cheating,
else normal; floor-change two-sided `FDWALLCOLORS+lightlev`; ceiling-change
`CDWALLCOLORS+lightlev`; flat two-sided `TSWALLCOLORS` only when cheating; unseen-but
allmap powerer `GRAYS+3`. Palette bases: `WALLCOLORS REDS`, `TSWALLCOLORS GRAYS`,
`FDWALLCOLORS BROWNS`, `CDWALLCOLORS YELLOWS`, `THINGCOLORS GREENS` (am_map.c:71–79) —
red walls ARE the vanilla default. `lightlev` strobes every tic via
`litelevels[] = {0,4,7,10,12,14,15,15}` (8-tic cycle, am_map.c:787–794).

Things: uniform tiny thin-triangle line-character at `t->angle`, color
`THINGCOLORS+lightlev` (AM_drawThings 1285+) — NO per-monster colors in vanilla.
Players: white arrow (`player_arrow`), `WHITE`; netgame other players cycle
`{GREENS,GRAYS,BROWNS,REDS}`. Grid: `AM_drawGrid` lines at every `MAPBLOCKUNITS<<FRACBITS`
= 256 world units, aligned to `bmaporgx/y` (blockmap aligned, “flat tile aligned”).

Lumps used: ONLY `AMMNUM0..9` (mark number patches, `AM_loadPics`, drawn 5×6 px — source
hardcodes w=5,h=6 “because something's wrong with the wad”). No other AM_* lumps exist.
Messages: AMSTR_FOLLOWON/OFF “Follow Mode ON/OFF”, AMSTR_GRIDON/OFF, AMSTR_MARKEDSPOT
“Marked Spot”, AMSTR_MARKSCLEARED “All Marks Cleared” (d_englsh.h:326–333 — IP rewrite).

Confidence §5: HIGH.
