0.1. **The 1.10 audio architecture is TWO layers — the brief's model of a mixer-only `i_sound.c` is half right.** `s_sound.c` = the game-facing channel allocator + audibility math (channels = `channel_t {sfxinfo, origin, handle}`, `numChannels` from `m_misc.c:282` default **3** (!), `snd_channels` config); `i_sound.c` = the Linux OSS software mixer with its OWN `NUM_CHANNELS 8` sample-level channels (:94), `SAMPLERATE 11025` (:99), 16-bit stereo `mixbuffer` (:112), `vol_lookup[128*256]` built as `i*(j-128)*256/127` (:421-423), and per-channel 0.16-step pointers (:599-603). `S_Init (snd_SfxVolume, snd_MusicVolume)` at d_main.c:1107; **`S_UpdateSounds(players[consoleplayer].mo)` runs once per FRAME in `D_DoomLoop` (d_main.c:392, inside the :354-398 loop, after TryRunTics)** — not in the tic block; the browser mapping (§3 D-10f) schedules from the per-tic event ledger at tic boundary times.

0.2. **`S_StartSound(origin, sfx_id)` (s_sound.c:397-407) → `S_StartSoundAtVolume(origin, id, snd_SfxVolume)` (:254-395) verbatim rules**: (1) `link` handling (:283-299) — ONLY `chgun` has a link (`&S_sfx[sfx_pistol]`, pitch 150, volume 0, sounds.c row 86): pitch=pitch-from-link, `volume += sfx->volume`, clamp `1..snd_SfxVolume`, drop if <1; non-link: `pitch=NORM_PITCH(128)`, `priority=NORM_PRIORITY(64)` — **the table's `priority` column is NEVER consulted on the play path** (:264/:286 locals are dead — priority is used ONLY by `S_getChannel` eviction, §0.4); (2) audible? if `origin && origin != players[consoleplayer].mo` → `S_AdjustSoundParams` (§0.3), same-xy override `sep=NORM_SEP` (:312-316), inaudible ⇒ return; else `sep=NORM_SEP` (:323); (3) **pitch jitter via `M_Random()`** (:326-346): saw family (sawup..sawhit) `pitch += 8-(M_Random()&15)`, ALL others EXCEPT itemup/tink `pitch += 16-(M_Random()&31)`, clamp 0..255 — **FINDING (the milestone's biggest): every S_StartSound burns one menu-stream `M_Random()`** (the brief's premise "1.10 has no PRNG in sfx" is wrong for linuxdoom-1.10; Chocolate's s_sound.c removed the jitter). Retirement route: D-10a (§3) — our engine must NOT add these draws (would desync `st_face`/WI ledgers and re-bless goldens); jitter comes from a sound-owned PRNG instead. (4) `S_StopSound(origin)` kill-old (:349, :471-484 — first channel with matching origin, one sound per origin); (5) `S_getChannel` (§0.4); (6) lazy `lumpnum = I_GetSfxLumpNum(sfx)` (:364-365; i_sound.c:451-456 — **`sprintf("ds%s", sfx->name)` ⇒ lump `DS*`**, W_GetNumForName, error if absent); (7) `usefulness++` cache bookkeeping (dead in 1.10 — pre-cached forever, i_sound.c:796-811); (8) `handle = I_StartSound(id, volume, sep, pitch, priority)` (:389-394) — **in linuxdoom `I_StartSound` IGNORES priority outright (i_sound.c:480)** and ignores/stores the rest via `addsfx` (§0.5).

0.3. **`S_AdjustSoundParams` (s_sound.c:752-818) — attenuation AND panning, verbatim.** Distance = GG1 approx-euclidean `adx+ady-min(adx,ady)>>1` on **x/y only, no z term** (:767-771; our SfxEvent's z stays informational). Clip: `gamemap != 8 && dist > S_CLIPPING_DIST(1200*FRACUNIT)` ⇒ inaudible (:55/:773-777). **Panning EXISTS in 1.10** (the brief's "no panning" premise is FALSE): source→listener angle delta via `R_PointToAngle2` (:780-788), `*sep = 128 - (FixedMul(S_STEREO_SWING=96*FRACUNIT, finesine[angle]) >> FRACBITS)` (:793, S_STEREO_SWING :74) — sep 0..256, 128=center; the **L/R split happens in the mixer `addsfx` (i_sound.c:350-373): `sep+=1; leftvol = vol - ((vol*sep*sep)>>16); sep-=257; rightvol = vol - ((vol*sep*sep)>>16)`** (quadratic law, clamp-check 0..127 via `vol_lookup` slices). Volume (:796-815): `dist < S_CLOSE_DIST(160*FRACUNIT :61)` ⇒ `vol = snd_SfxVolume`; `gamemap==8` special ⇒ `vol = 15 + ((snd_SfxVolume-15)*(CLIP-dist>>FRACBITS))/S_ATTENUATOR` (:800-808, no clip-out); else linear ramp `vol = snd_SfxVolume*((CLIP-dist>>FRACBITS))/S_ATTENUATOR` with **`S_ATTENUATOR = (1200-160)>>FRACBITS = 1040`** (:64) — note R10 §2.4 quoted Chocolate's `S_CLOSE_DIST=200` (1000); **linuxdoom-1.10 truth is 160/1040 — pin the mirror**. Audibility = `vol > 0` (:817). Per-frame re-application: `S_UpdateSounds` (:519-613) re-runs the params for every live channel each frame (`I_UpdateSoundParams` :597) — but **linuxdoom's `I_UpdateSoundParams` is a documented NO-OP (i_sound.c:675-688, "I fail to see that this is used") ⇒ in the mirror, positional params freeze at start; Chocolate applies them per-frame.** Decision D-10e: we APPLY per-tic updates (the roadmap exit says "attenuation/panning" as a live property; freezing makes it decorative).

0.4. **`S_getChannel` (s_sound.c:827-875) — the priority rule, exact**: scan channels in order; break on first FREE one, **but break-and-steal if a channel is occupied by the SAME origin** (:838-847, one-sound-per-mobj — this is the real "singularity"; the `singularity` table column is never read in 1.10 except via the hardcoded dedup list in `addsfx`, §0.5); if none: scan for `channels[c].sfxinfo->priority >= new->priority` and kick out the FIRST such channel (:850-865 — LOWER number = higher precedence, "Otherwise, kick out lower priority"), else `return -1` "Sorry, Charlie" (:856-860). Plus `S_StopChannel` (:708-742, `usefulness--`, no-op stop in linuxdoom's `I_StopSound` :505-514). The 1.10 `S_sfx[]` priorities transcribe (sounds.c:114-227, 108 entries + dummy; the ONLY non-false "looping" flag is on the 17 `*sit/*act/itemup/wpnup/posit/bgsit`-family rows — the field is also never read in 1.10; looped sfx (bspwlk etc.) are Doom-2 ambience our WAD never triggers — §4). Enum: sfx_None=0 … sfx_radio=108, NUMSFX=109 (already transcribed on main: `psound_stub.ts SFX_ID`). Full table = (name, looping, priority) rows 0-108; the port keeps the generated table, M10-02 adds the (priority, lump-availability) audio mirror.

0.7. **Volume plumbing (the L4 exit target).** Globals `snd_SfxVolume = snd_MusicVolume = 15` (s_sound.c:113/:116) are OVERRIDDEN by defaults `{"sfx_volume",…,8}/{"music_volume",…,8}` (m_misc.c:237/:238) and applied at load via `S_SetSfxVolume(snd_SfxVolume /* *8 */)` (m_misc.c:830) / `S_SetMusicVolume(… /* *8 */)` (:847) — **the `*8` is COMMENTED OUT in every 1.10 call site (m_menu.c:830/:847, d_main.c:1107)**: the Linux port runs the 0..127-scale engine at menu-scale 0..15, so at default 8 every attenuated distant sound is `8*dist-ramp/1040 ≈ 0` ⇒ the 1.10 binary is functionally near-silent beyond point-blank (DOS-era semantics were `thermo*8`, i.e. 0..120). Menu thermo 0..15: `M_SfxVol/M_MusicVol` (m_menu.c:820-849, SoundDef status-2 rows :433/:435, alphaKeys 's'/'m') — our menu.ts ALREADY stores `sndSfxVolume/sndMusicVolume` defaults 8 with the exact ±1 clamps (menu.ts:247-248/:648-662) and exposes `sndVolumes()` (:373). `S_SetMusicVolume` (s_sound.c:616-627) validates 0..127 and pushes one global driver volume. Decision D-10d: restore `*8` (0-15 → 0..120 internal), sfx bus linear `v/127`, music bus `mv*8/127` × music-trim constant.

0.8. **SFX lump format (R10 §1 re-verified against the pinned WAD):** DS lumps = `[u16 format=0x0003][u16 LE sampleRate][u32 LE sampleCount][raw unsigned-8-bit PCM, center 128]`, `lumpLen == 8 + count` for all 69 (measured hexes: DSPISTOL 22050 Hz/11026, DSDOROPN 22050/36371, DSSAWFUL 22050/10178, DSOOF 22050/7875, DSHOOF 17990, DSBAREXP 22050/22466 — header bytes `0300` + rate-LE + len-LE ✓). **Arbitrary rates must be supported: {22050×44, 11025×22, 17990, 16000, 44100}** (measured histogram == R10 §1.3). NO 0x7F escape (confirmed by R10's histograms); vanilla's own 11025 mixer rate is irrelevant to us (we resample at decode). Decode → Float32 mono AudioBuffer with linear interpolation `n = targetRate/headerRate` (R10 §1.2 recipe). The 61 **DP\*** lumps in the WAD are DMX-style `{0,length}` micro-stubs (DPPISTOL = 18 B) referenced by NO code path in the mirror or Chocolate (lookup is `ds%s`, i_sound.c:454) — catalogued, ignored, §4.
